# mcapra.github.io

A Hugo site published to GitHub Pages at https://mcapra.github.io/. Most of it is a library of Magic: The Gathering Commander decks: a filterable gallery, and a page per deck with a **Decklist** tab (the full list with role, color and mana value filters) and an **Overview** tab (a short guide to playing the deck).

Deck pages are meant to stand on their own. A reader should understand a deck without visiting Moxfield or Archidekt; links to those sites are fine as extras, but never the only source of information.

## Running it locally

Everything runs inside a container image (`.devcontainer/Dockerfile`) that has Hugo and Python, so the host only needs Podman (or Docker).

```sh
./dev.sh                          # Hugo dev server with drafts, on your LAN IP:1313
./dev.sh python build_card_db.py  # run any other command in the container
```

- The server uses your LAN address so phones on the same network can follow links. If it picks the wrong interface, set it yourself: `HUGO_HOST=mybox.local ./dev.sh`.
- Run from a Flatpak editor's terminal (e.g. VSCodium), `dev.sh` re-runs itself on the host, where Podman lives.
- In VS Code or Codespaces, "Reopen in Container" uses `.devcontainer/devcontainer.json` instead. VSCodium can't do this (Microsoft's Dev Containers extension is VS Code-only), so use `dev.sh` there.
- VS Code / VSCodium tasks: **Hugo: serve** (the default build task, Ctrl+Shift+B), **Build card database** and **Check decks**.

Hugo is pinned to **0.115.4** in both the Dockerfile and `.github/workflows/hugo.yaml`; change them together. Newer Hugo versions remove things the paper theme relies on.

## Repository layout

| Path | What it is |
|---|---|
| `content/posts/mtg_decklists/<slug>/index.md` | A deck: all its metadata and its Overview, in TOML front matter. The body is unused. |
| `content/posts/mtg_decklists/<slug>/deck.yaml` | The card list. Generated by `import_decks.py`. |
| `content/posts/mtg_decklists/<slug>/roles.yaml` | Curator overrides for card roles. Never touched by scripts. |
| `content/posts/mtg_decklists/<slug>/qr.png` | Printable QR code for the deck's page. Generated by `generate_qr.py`. |
| `content/posts/mtg_decklists/_index.md` | The deck gallery page. Its `cascade` applies the deck layout to every deck post. |
| `data/cards.json` | Every card the site references (name, cost, type, color identity, image, roles). Generated by `build_card_db.py`; commit it. |
| `data/roles.yaml` | The card roles ("Rocks", "Tutors", "Win Cons"...) and the Scryfall searches that pre-fill them. |
| `data/archetypes.yaml` | The deck archetype vocabulary ("Combo", "Stax"...) with one-line definitions. |
| `layouts/_default/deck.html`, `layouts/_default/decks.html` | The deck page and the gallery. |
| `layouts/partials/mtg/` | Deck rendering: list resolution, card lookup, filters, overview, card links. |
| `layouts/partials/head.html` | Override of the theme's head: identical except the stylesheet is fingerprinted (see [Troubleshooting](#troubleshooting)). |
| `assets/custom.css`, `assets/js/mtg.js` | All deck styling and behavior (tabs, filters, card viewer, gallery filters). |
| `archetypes/decklist/` | Template for `hugo new --kind decklist`. |
| `ingest_deck.py` | One-command deck ingestion: draft post, card list, card data, Spellbook combos and a research brief. |
| `import_decks.py` | Refreshes existing decks' card lists from Moxfield or Archidekt. |
| `build_card_db.py` | Resolves every referenced card through Scryfall into `data/cards.json`. |
| `generate_qr.py` | Writes each deck's printable QR code. |
| `check_decks.py` | Checks deck posts for mistakes; also runs in CI before every deploy. |
| `dev.sh`, `.devcontainer/` | Local development container. |

## Adding a deck

Run commands through `./dev.sh` (or inside the dev container).

1. **Ingest the deck** from its Moxfield or Archidekt URL:

   ```sh
   ./dev.sh python ingest_deck.py https://moxfield.com/decks/XXXXXXXX
   ```

   This creates a draft post named `b<bracket>-<commander>`, fills in the bracket and commanders, imports every card at its exact printing, resolves the cards into `data/cards.json`, generates the QR code, and adds up to three of Commander Spellbook's infinite combos to Key Combos. Options:
   - `--bracket 3` and `--slug b3-my-deck` override what the source reports.
   - `--precon 'Product Name'` marks a preconstructed deck instead of crediting an author.
   - `--primer input/my_primer.json` includes a primer in the research brief. Moxfield has no public primer endpoint and blocks scripted page requests, so save the primer's JSON from your browser (the request the primer page makes, visible in the developer tools).

   Re-running on an existing deck only rewrites the brief, so it's safe to add a primer later.

2. **Check the credit.** Moxfield's `originalDeck` field means a duplicated deck credits the original builder automatically. Archidekt has no equivalent, so a copied Archidekt deck credits its owner; fix `deck_authors` by hand.

3. **Choose `archetypes`**, primary first. Every name must exist in `data/archetypes.yaml`; add new ones there with a one-line definition.

4. **Curate roles** in `roles.yaml` (see [Card roles](#card-roles)). At minimum, mark the deck's real finishers with `win-condition`.

5. **Write the Overview**, replacing the TODOs in the `[overview]` table. `ingest_deck.py` writes a research brief to `.cache/ingest/<slug>.md` with the commander's text, land count, color weights, cheap ramp, curve, roles, every card by type and any primer. The prose is left to you because it needs judgment; see [Writing an overview](#writing-an-overview). Then remove `draft = true`. A published deck with TODOs fails `check_decks.py`.

6. **Check** the deck, including the online combo check:

   ```sh
   ./dev.sh python check_decks.py --spellbook b4-my-deck
   ```

7. **Preview** with `./dev.sh`, on a phone as well as a desktop browser; the site is primarily read on phones.

8. **Commit** `index.md`, `deck.yaml`, `roles.yaml`, `qr.png` and `data/cards.json` together.

To build a deck by hand instead, run `./dev.sh hugo new --kind decklist posts/mtg_decklists/b4-my-deck` and write `deck.yaml` yourself (see [deck.yaml](#deckyaml)) without the `# Imported by import_decks.py` header; the importer then leaves it alone.

## Writing an overview

The Overview replaces long primers: a reader should get the deck in a minute. It has these sections, each shown only when it has content:

- Summary
- Strengths
- Weaknesses
- Key Combos
- Rulings
- Gameplan
- Mulligan For

These rules come from mistakes made while drafting the first 50.

### Verify everything against the list

- **Every card you name must be in the deck's current list.** Primers go stale: on review, combos named in primers (Kiki-Jiki in Henzie, Doomsday in Yuriko, Veyran's infinite-copy pieces) had already left the lists. Check names against `deck.yaml`, not against the primer.
- **Get colors and costs from `data/cards.json`, not memory.** Zinnia's precon was first written up as Boros; it's Jeskai. Hashaton costs {W}{B}, though the deck is mostly black and blue.
- **Get counts from the list** (lands, cheap ramp, how many cards at 6+ mana value) rather than estimating.

### Decks without a primer

Read the exact text of the commander and the deck's key cards, then look at how the commander is played (EDHREC, Draftsim and similar guides). The most useful interactions come from reading this list's cards together; for example, Tom Bombadil's list has Barbara Wright, whose read ahead lets any Saga start on its final chapter. Check whether effects say "cast" or "enters": it decides what triggers from cards put onto the battlefield for free.

### Summary

One or two sentences: colors, the engine, and how the deck wins.

### Strengths and Weaknesses

Two to four each, specific to *this list*. "Plenty of card draw" is filler; "Ool turns every -1/-1 counter into a card or a point of drain" says something. Weaknesses should name what actually beats the deck (e.g. "Weak to nonbasic land hate: Back to Basics, Blood Moon").

### Key Combos

- **Always call out an infinite combo if the deck has one.** Check the list with [Commander Spellbook](https://commanderspellbook.com)'s "Find My Combos". Mark those combos `kind = "infinite"` (or `"win"` for lines like Thassa's Oracle that win without an infinite loop) and set `source` to the combo's Spellbook page. Badged combos are shown first.
- Give each combo the cards involved and a one-line `result`.
- Add numbered `steps` where the sequence matters: always for Bracket 5, and for intricate Bracket 4 lines. Length is fine there.
- Non-infinite synergies are welcome too, but don't oversell them.

### Rulings

Only non-obvious rules interactions a player could get wrong. For example, Necropotence's discard triggers give players priority in the cleanup step, and Light-Paws' Aura tutor doesn't target. Cite a Comprehensive Rules number only when certain of it.

### Gameplan

Two or three bullets on how the deck plays out, often early, mid and late game, with the turn each key piece should land. Check turn claims against mana costs: a 5-mana commander doesn't come down on turn three.

### Mulligan For

The most error-prone section. Each line should tell a player something they couldn't guess from the commander's name.

- **Lands:** how many to keep, given this deck's land count, and *which colors carry the deck*. Count the colored mana symbols across the 99; the commander's colors can be misleading. Ashling costs {2}{R}, but her deck is overwhelmingly green. Henzie needs red, though red is the deck's lightest color.
- **Pieces:** what the first turns need for *this strategy*, by role or by card. For example: a reanimation target plus a way to discard it, a sacrifice outlet plus fodder, or a Court so Obeka's first hit has something to multiply.
- **Avoid generic advice.** "Plus a Rock" or "look for Sol Ring" applies to every deck. Mention ramp only when the deck depends on it, and say what kind and how many it runs.
- **If a line is unclear,** say what it actually means. "Colored mana to match your Humans" really meant "fix for five colors, because the Humans span all of them and the mana base is light on fixing".

### Precons

Use `precon = 'Product Name'` instead of `deck_authors`. Precons rarely have primers, so read a couple of reviews (EDHREC precon reviews and upgrade guides, Card Kingdom upgrade guides) and fold in what reviewers say about the stock list's strengths and weaknesses. Coverage varies a lot by product; where it's thin, rely on the list itself.

## Checking decks

`check_decks.py` automates the mechanical parts of [Verify everything against the list](#verify-everything-against-the-list). It runs offline in CI before every deploy, so a failing check blocks publishing.

```sh
./dev.sh python check_decks.py                        # every deck
./dev.sh python check_decks.py b4-my-deck             # just these decks
./dev.sh python check_decks.py --spellbook            # also ask Commander Spellbook (online)
```

**Errors** (exit status 1):

- Required front matter is missing.
- A published deck still has `ingest_deck.py` TODOs, or has no archetypes or summary (drafts only get a warning).
- An archetype isn't in `data/archetypes.yaml`.
- The deck has both or neither of `deck_authors`/`precon`.
- A card is missing from `data/cards.json`.
- A Key Combos or Rulings card isn't in the deck.
- A combo `kind` or `source` is invalid.
- `roles.yaml` names a card that isn't in the deck, or a role that doesn't exist.
- A Mulligan For line says "of the N lands" and N doesn't match the list.
- `qr.png` is missing, too small to print at 2cm, points to a URL other than the deck's, or has a wrong or duplicate ID (drafts only get a warning for a missing code).

**Warnings:**

- The deck isn't 100 cards.
- An Overview section is missing.
- With `--spellbook`: Commander Spellbook finds infinite or game-winning combos and none is in Key Combos. The warning names one to add, with its link.

Add `--strict` to fail on warnings too. The check can't judge prose: colors, turn claims and whether advice is specific still need a careful read.

## Reference: deck files

### Front matter (`index.md`)

| Field | Required | Notes |
|---|---|---|
| `title` | yes | `[Bracket N] Name`. The page heading shows the commanders' card names instead. |
| `bracket` | yes | 1–5. Drives the gallery's bracket filter. |
| `commanders` | yes | Card lines, e.g. `"Burakos, Party Leader (CLB) 653"`. Partners and backgrounds are separate entries. |
| `archetypes` | yes | From `data/archetypes.yaml`, primary first. |
| `decklist_url` | to import | Moxfield or Archidekt deck URL. Not shown on the page. |
| `primer_url` | no | Where an old primer came from. Not shown on the page. |
| `deck_authors` | one of | `[{ name = '...', url = '<profile>' }]`; shown as "By …". |
| `precon` | one of | Product name for preconstructed decks; shown as "Precon · …". |
| `[overview]` | yes | `summary`, plus lists `strengths`, `weaknesses`, `gameplan`, `mulligan`. |
| `[[overview.combos]]` | no | `cards`, `result`; optional `kind` (`infinite`/`win`), `steps`, `source`. |
| `[[overview.rulings]]` | no | `cards`, `note`. |

### deck.yaml

Card lines use Moxfield's text export format: `1 Sol Ring (CMM) 410`. The printing `(SET) number` is optional but pins the art. Lines starting with `#` or `//` are ignored.

```yaml
cards: |                 # grouped by card type automatically
  1 Sol Ring (CMM) 410
  10 Island
sideboard: |             # optional; excluded from counts and the copied list
  1 Mystic Remora
```

Instead of `cards`, a hand-built list can use custom `sections` (`- name: Ramp` with its own `cards`), and entries can be maps with a `note`.

### Card roles

Roles power the Decklist tab's role filters. `build_card_db.py` pre-fills them from [Scryfall Tagger](https://tagger.scryfall.com) searches defined in `data/roles.yaml`; those are community hand-curated tags, cached in `.cache/` for a week.

To correct a card in one deck, list it in that deck's `roles.yaml` with *all* the roles it should have. An entry replaces the pre-filled roles rather than adding to them:

```yaml
"Craterhoof Behemoth": [win-condition]
"Cyclonic Rift": [removal, board-wipe]
```

Only alternate-win cards are pre-tagged as Win Cons, so marking each deck's actual finishers is a curator job.

## Keeping data current

- **A source list changed:** `./dev.sh python import_decks.py --refresh b4-my-deck`, then `./dev.sh python build_card_db.py`. `--refresh` only rewrites `deck.yaml` files that still carry the import header. Re-check the Overview's combos afterwards, since cards may have left.
- **Role definitions changed:** edit `data/roles.yaml`. The next `build_card_db.py` run refetches automatically when a query changes, or force it with `--refresh-roles`.
- **Offline card data:** `build_card_db.py --bulk oracle-cards.json` uses a Scryfall bulk-data file instead of the API.
- **Rate limits:** the scripts pace themselves: Moxfield and Archidekt at one request per second, Scryfall at two. If Scryfall answers with HTTP 429, the script waits the requested 60 seconds before retrying.

## QR codes

Each deck folder has a `qr.png` linking to its page, published at `<deck URL>/qr.png`. The QR pattern is 259px wide, and the whole image, with its white quiet zone and label, is 315×359px. At the embedded 300dpi that's a 2.19cm code on a 2.67×3.04cm image. Print at 100% with no "fit to page" scaling, and don't crop the white border; scanners need it. Every deck uses the same QR version, so all codes print the same size.

Under each code is a 6-character ID so printed codes can be matched to decks without scanning: the bracket plus the first four letters of the slug (`b3-tom-bombadil` is `b3tomb`). Slugs too short for that use the commander's name instead (`b2-omo` is `b2omoq`). `check_decks.py` fails if two decks share an ID; rename one deck's folder to fix it.

`ingest_deck.py` generates the code for new decks. **After renaming a deck folder**, regenerate its code, since the URL changes (and any copies you've already printed will stop working):

```sh
./dev.sh python generate_qr.py b4-my-deck    # or no name for every deck
```

The URL comes from `baseURL` in `hugo.toml`. It's stored in each PNG along with the ID, so `check_decks.py` can catch a stale code. `generate_qr.py` needs `segno` and Pillow, so run it (and `ingest_deck.py`) through `./dev.sh`.

## Deploying

Pushing to `main` runs `.github/workflows/hugo.yaml`, which builds with Hugo 0.115.4 and publishes to GitHub Pages. The build needs no network access for deck data, since everything comes from the committed `data/cards.json`.

## Troubleshooting

- **Changes don't show on a phone, but do on desktop.** iOS Safari caches aggressively. The site fingerprints its CSS and JS (so URLs change with content) and `dev.sh` serves with `--noHTTPCache`. If a phone still shows stale styles, close the tab and open a fresh one.
- **The filters or tabs stop working only on the dev server.** Make sure page scripts aren't emitted "once per page" via `.Scratch`: in Hugo 0.115's dev server, Scratch survives re-renders, so the script silently disappears after the first render. The deck layout always includes its script for this reason.
- **"Card not in data/cards.json" warnings.** Run `build_card_db.py`. If a name still fails, check the spelling, or whether the printing exists on Scryfall.
- **A template change breaks with "wrong type for value; expected bool".** Hugo's `cond` needs a real boolean and evaluates both branches; use `if`/`else` instead.
